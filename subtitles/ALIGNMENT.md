# 配音与字幕校准记录

本次范围：开头40.8秒样片。原文保留在 source/，原始字幕不覆盖。

## 实际发现

- 分轨合并时包含约1.1倍速处理；每段原声的目标时长约为原时长的0.91倍。
- 插入另一角色对白造成多个不同的时间偏移。因此不能给整份SRT统一加偏移。
- 原始SRT编号不完全按时间排列；一些条目跨越被另一角色打断的多句话。
- 相同的“哦”“嗯”等短句会产生误匹配；静音也可能有高相关度。不能只用一个相关系数证明字幕准确。

## 本次处理

1. 音频转为8kHz单声道，用24个频带的对数谱特征匹配；以不同时间缩放搜索原分轨片段。
2. 保存采样窗口选出的匹配锚点及连续映射段，用连续语音的前后关系核查开头轮次。
3. 使用用户SRT提供的文本，以原文稿校正标点和“211/120/130”等数字表达。
4. 将开头跨轮次条目拆开，利用完整对话的静音边界校准换人时间。
5. 输出 opening-captions.srt（纯字幕）与 opening-dialogue.srt（带角色标识）。Remotion直接读取src/opening-captions.ts中的同一份帧时间码。
6. 字幕入场不使用透明度动画；完整对白仍从第0帧连续播放，不裁剪、不重排。

## 复现

在仓库根目录，准备public/top-student/source/下的student.mp3、teacher.mp3、full-dialogue.mp3。
依赖：Python、numpy、scipy、ffmpeg。

```sh
python3 scripts/map-dialogue-audio.py
python3 scripts/build-opening-captions.py
npm run check
npm run render:student-sample
```

脚本默认重新计算全片匹配锚点，可能耗时数分钟。原始配音和音乐沿用本地忽略目录中的素材，未随此修订发布源音频。
